# Assessment evaluation and AI agent

Deterministic code computes every number. The LLM only (a) writes plain-language explanations,
(b) orders recommended topics with reasons, and (c) picks notes and practice questions from IDs the tools return.

## Scoring (apps/api/app/scoring) — pure functions with unit tests
- `topic_score_pct = marks_obtained / max_marks * 100` per topic.
- Class: `strong` ≥ 80, `weak` < 60, else `developing`; fewer than 3 questions → `insufficient`.
- `priority = 60 - score_pct` for weak topics (higher first).
- Misconception: same `misconception_id` chosen ≥ 2 times by the candidate.
- Item analysis per exam: p, D (top/bottom 27%), distractor shares; flag `D < 0` or a distractor chosen more by the top group than the key.
- All thresholds from config; never hard-coded.

## Agent run (apps/api/app/agent)
Triggered as a job when a session reaches `scored`. Uses the Anthropic SDK tool-use loop with model from `ANTHROPIC_MODEL`.
Tool registry is an allow-list; each call is logged to `agent_steps` (args, output summary, latency, error) and the run to `agent_runs` (model, prompt_version, tokens, cost).

| Tool | Returns | Notes |
|---|---|---|
| get_topic_results(session_id) | topics with score, class, n_questions | read-only |
| get_wrong_answers(session_id, topic_id) | question ids, chosen option, misconception | read-only |
| get_misconceptions(session_id) | misconception ids + descriptions | read-only |
| find_notes(topic_id, level) | approved note ids + titles | approved library only |
| select_practice_questions(topic_id, n, max_difficulty) | approved question ids | excludes questions already seen |
| draft_evaluation_summary(session_id, content) | summary_id | validates against `summary.schema.json`; rejects unknown note/question ids |
| submit_for_mentor_review(summary_id) | status | sets `draft` → review queue |

There is deliberately **no** publish tool and **no** write access to marks, events or flags.

## Guardrails (enforce in code)
- `draft_evaluation_summary` validates: every `note_id` exists and is approved; every topic id belongs to the exam; scores in the content equal the computed scores (reject if the model altered a number).
- If any topic is `insufficient` or subjective answers are unmarked, put that in `data_notes` and still draft; never guess.
- If no approved note matches a weak topic, set `notes: []` and `needs_mentor_note: true`.
- Tone: encouraging, specific, second person, no mention of proctoring, no judgement of effort or honesty. Max ~150 words of free text per summary.
- `integrity_note` is generated by a separate Integrity Summary step from counts only (flags n/3, glances, open reviews) — neutral facts, never conclusions.

## Mentor approval and publishing
- Endpoints: PATCH (edit, bumps `version`), `/request-changes` (agent redrafts with mentor comment), `/approve`, `/publish`.
- `/publish` returns 409 unless status is `approved`; creates the practice set; optional email notice.
- Candidate endpoints read only `published` summaries and strip `data_notes` and `integrity_note` in the response schema (separate Pydantic model, not a filter in the router).

## Files
- `summary.schema.json` — JSON schema for `content_json`.
- `prompt.md` — system prompt template for the agent (version it; store `prompt_version` on each run).
